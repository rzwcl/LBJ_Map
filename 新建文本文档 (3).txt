当前项目是针对 Qualcomm X55 / Hexagon QDSP6 基带固件进行静态逆向，目标不是改写整个 modem，而是：

找到 DIAG → FTM → RFDEBUG → RADIO_CONFIGURE → FREQUENCY 的真实固件调用链，最终理解怎样通过现有 RFDEBUG 接口配置接收侧频率。

0x30F316FC
LE: FC 16 F3 30

这不是目标频率，已经排除。

项目一直坚持：

只读
不写 modem

二、为什么我们一直在找 RFDEBUG 入口

真正的通信链已经通过动态测试确认了一部分。

用户发出的 DIAG 包：

4B 0B 7B 00 01 00 26 00 ...

含义：

0x4B = DIAG_CMD_SUBSYS
0x0B = FTM subsystem
0x007B = FTM subsystem command

这里最重要的一点：

0x7B 不是一个独立的 RFDEBUG subsystem ID。

而是：

DIAG_CMD_SUBSYS
    ↓
FTM SSID 0x0B
    ↓
FTM 内部 subsystem command 0x7B
    ↓
RFDEBUG

动态测试已经确认：

0x7A → 无响应
0x7C → 无响应
0x5555 → 无响应
0x7B → 返回了 RFDEBUG 格式的 25 字节响应

因此：

0x7B

这件事本身不是猜测，而是已经由动态行为证明了。
